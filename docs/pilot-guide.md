# Dhruva.AI — Synthetic Pilot Institution Operations Guide

**Scope**: Synthetic Pilot Testing, Product Demonstration, and End-to-End Workflow Validation  
**Institution**: Dhruva Demo University (`DHRUVA-DEMO-U`)  
**Safety Status**: `PILOT_ONLY` (Safeguarded against production contamination)  
**Dataset Version**: `1.0.0`

---

## 1. Overview & Operational Principles

The Dhruva.AI Synthetic Pilot Institution provides an isolated, deterministic, and realistic academic environment designed to validate all 12 operational domains under simulated institution-scale conditions.

### Core Invariants:
1. **Zero Production Contamination**: Synthetic pilot scripts will immediately abort if executed in `ENVIRONMENT=production` unless `ENABLE_SYNTHETIC_PILOT_DATA=true` is explicitly provided.
2. **Deterministic Engine Authority**: Student metrics (mastery, retention decay, career trajectories, remediation triggers) are generated by actual backend mathematical engines (Domains 6–10), not hardcoded numbers.
3. **Identity Privacy**: All synthetic users employ the RFC 2606 reserved `.invalid` top-level domain (`@example.invalid`) and clearly labeled demo identifiers (`Demo Faculty`, `STU-DEMO-xxx`).

---

## 2. Quickstart: Seeding the Pilot Institution

### Full Automated Seeding (All Domains)
From the repository root or `backend/` directory with the virtual environment activated:

```bash
cd backend
python -m app.scripts.seed_all
```

This single command executes 6 transactional phases in sequence:
1. **National Catalog**: AICTE disciplines, degree types, programs, specializations, skills, and career mappings.
2. **Canonical Courses & DAG**: 12 core courses, 35 concepts, and 28 prerequisite directed acyclic graph edges.
3. **Question Banks & Blueprints**: 5 question banks, coding sandbox test cases, and diagnostic assessment blueprints.
4. **Project Templates**: 9 engineering project templates across Beginner, Intermediate, and Advanced tiers.
5. **Pilot Institution & Cohorts**: `DHRUVA-DEMO-U`, 5 departments, 5 faculty, 4 offerings, and 50 synthetic students.
6. **RAG Knowledge Base**: 35 approved and published concept knowledge chunks for AI retrieval.

### Granular Seeding Commands
Individual layers can also be seeded independently:
```bash
python -m app.scripts.seed_catalog
python -m app.scripts.seed_courses
python -m app.scripts.seed_questions
python -m app.scripts.seed_projects
python -m app.scripts.seed_demo_institution
python -m app.scripts.seed_rag
```

All seed scripts are **100% idempotent**. Running them multiple times will never duplicate records or corrupt existing mappings.

## 4. End-to-End Operational Workflows

### Workflow 1: Student Learning & Autonomous Remediation
1. **Login**: Navigate to `/login` and authenticate with `stu.demo.026@example.invalid`.
2. **Inspect Mastery**: Navigate to `/knowledge` to observe low mastery in `CON-DSA-LL` (Linked Lists) caused by an unfulfilled prerequisite in `CON-PY-BASICS`.
3. **Autonomous Remediation**: Navigate to `/remediation`.
   - Observe the active `RemediationPlan` auto-generated by Domain 10.
   - Diagnosis category: `PREREQUISITE_GAP`.
   - Follow the prescribed micro-learning modules and targeted practice assessments.
4. **Reassessment & State Transition**:
   - Complete the review assessment at `/remediation/[id]`.
   - On submission, Domain 10 re-evaluates the evidence, transitions the remediation plan to `COMPLETED`, and updates the knowledge state.

### Workflow 2: Faculty Assessment & Evaluation
1. **Login**: Authenticate with `faculty.cse01@example.invalid`.
2. **Course Offerings**: Navigate to `/faculty` to view assigned offerings (`OFFER-2026-FALL-PY` and `OFFER-2026-FALL-DSA`).
3. **Assessment Blueprint**: Navigate to `/assessments` to view the Python Diagnostic Blueprint (`BP-PY-DIAG-01`).
4. **Grading & Review**: Navigate to `/faculty/grading` to review pending manual or coding submissions.
5. **AI Copilot**: Navigate to `/faculty/ai` to request class-wide diagnostic summaries grounded in assigned student performance.

### Workflow 3: HOD Academic & Departmental Analytics
1. **Login**: Authenticate with `hod.cse@example.invalid`.
2. **Department Dashboard**: Navigate to `/hod` to review department-wide aggregate metrics:
   - Average concept mastery across courses.
   - Distribution of prerequisite gaps in early semesters.
   - Active academic intervention signals.
3. **Intervention Signals**: Review at-risk students flagged by Domain 9 (`Cohort 6`, `STU-DEMO-047` to `050`).
4. **AI Assistant**: Navigate to `/hod/ai` to query departmental curriculum bottlenecks.

### Workflow 4: Placement Readiness & Career Intelligence
1. **Login**: Authenticate with `placement@example.invalid`.
2. **Readiness Dashboard**: Navigate to `/placement` to inspect career readiness distribution across the 50 pilot students:
   - *Tier 1 (Ready)*: Cohort 1 students with verified portfolios and mastery >0.80.
   - *Tier 2 (Developing)*: Cohort 2 and 5 students progressing through core skill paths.
   - *Tier 3 (Not Assessed / At Risk)*: Cohort 3 and 6 students with prerequisite gaps.
3. **Career Pathways**: Navigate to `/career` to view deterministic skill coverage for roles like `Full Stack Developer` and `Machine Learning Engineer`.

### Workflow 5: RAG Grounded AI Mentor Interaction
1. **Student Context**: As `stu.demo.001@example.invalid`, navigate to `/ai`.
2. **Contextual Query**: Ask:
   > *"What concepts should I study next to prepare for Tree traversal algorithms?"*
3. **Verification**:
   - System retrieves `CON-DSA-TREES` knowledge chunks indexed in Domain 13.
   - Response provides exact prerequisite citations (`CON-DSA-RECURSION`, `CON-DSA-LL`).
   - The AI explains the deterministic mastery records without hallucinating scores.

## 5. Resetting & Cleansing Pilot Data

To safely wipe and re-seed the synthetic pilot institution without affecting any production or tenant configuration:

```bash
cd backend
# Delete and recreate pilot tables in non-production environment:
python -c "
import asyncio
from app.core.database import engine, Base
async def reset():
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all)
        await conn.run_sync(Base.metadata.create_all)
asyncio.run(reset())
"

# Re-run the full idempotent seed pipeline:
python -m app.scripts.seed_all
```
